

  1. 초기 오류 수정 및 라우팅 구조 개선


   * 데이터 로딩 오류 해결:
       * api/index.js의 API 함수가 데이터를 반환(return)하지 않고 콘솔에
         출력(console.log)만 하고 있어, 실제 데이터가 컴포넌트로 전달되지 않는 문제를   
         수정했습니다.
       * HomePage.jsx에서 API 함수를 호출한 후, 반환된 데이터를 useState를 통해 상태에  
         저장하도록 로직을 추가했습니다.
   * 라우팅 문제 해결:
       * App.jsx의 라우터 설정에서 Nav 컴포넌트가 다른 페이지들을 감싸고 항상 표시되도록
         Outlet을 사용하는 구조로 변경했습니다.
       * HomePage가 기본 경로(/)에 제대로 표시되도록 index: true 옵션을 사용하여 라우팅 
         구조를 개선했습니다.

  2. 전체 리팩토링 (코드 구조 개선)


   * 상태 관리(Zustand) 통합:
       * LoginPage와 SignupPage에서 각각 사용되던 useAuthStore와 useSignUpStore를
         useUserStore 하나로 통합했습니다.
       * 이를 통해 사용자 인증 및 회원가입 관련 상태(이메일, 비밀번호, 이름, 로그인 상태   
         등)를 한 곳에서 효율적으로 관리하도록 개선했습니다.
   * 컴포넌트 재사용성 증대:
       * LoginPage와 SignupPage에 중복되던 입력 폼 UI와 로직을 AuthForm이라는 별도의       
         컴포넌트로 분리했습니다.
       * 이를 통해 코드 중복을 제거하고, 로그인과 회원가입 폼을 하나의 컴포넌트로 관리할 수
         있게 되어 유지보수성이 향상되었습니다.
   * API 및 데이터 전달 방식 개선:
       * api/index.js의 getMovieDetial 함수가 movieId를 객체 형태로 받던 것을, id 값만     
         받도록 명확하게 수정했습니다.
       * DetailPage.jsx에서 useParams로 받은 id를 Info 컴포넌트로 직접 전달하도록 수정하여 
         데이터 흐름을 더 직관적으로 만들었습니다.
   * 코드 정리:
       * 개발 중에 사용되었던 불필요한 console.log 구문들을 프로젝트 전반에 걸쳐
         삭제했습니다.
       * Card.jsx에서 사용되지 않는 index prop을 제거하여 코드를 더 깔끔하게 다듬었습니다.

  이미지 사이즈를 original에서 w500으로 변경한 이유


  가장 중요한 변경 중 하나는 카드에 표시되는 이미지 주소를 TMDB API의 original
  사이즈에서 w500 (가로 500px) 사이즈로 변경한 것입니다. 이는 성능 최적화와 사용자 경험 
  향상을 위해 필수적인 작업입니다.


   1. 성능 (로딩 속도)
       * original 이미지는 수천 픽셀에 달하는 고해상도 원본 파일로, 파일 용량이 매우     
         큽니다 (수 MB에 달할 수 있음).
       * 홈페이지에서 수십 개의 카드 이미지를 original 사이즈로 불러오면, 웹페이지가 모든
         이미지를 다운로드하는 데 시간이 오래 걸려 페이지 로딩 속도가 현저히 느려집니다. 
       * w500 이미지는 카드 크기에 적합하게 리사이즈된 작은 파일이므로 다운로드 속도가   
         훨씬 빠릅니다. 결과적으로 사용자는 페이지에 더 빨리 접근할 수 있습니다.


   2. 데이터 사용량
       * 모바일 사용자나 인터넷 속도가 느린 환경의 사용자는 큰 용량의 이미지를 로딩하는 데
         많은 데이터를 소모하게 됩니다.
       * 필요 이상으로 큰 이미지를 제공하는 것은 사용자의 데이터를 낭비하는 것이며, 이는  
         특히 데이터 요금제에 민감한 사용자에게 좋지 않은 경험을 줍니다. w500으로
         변경함으로써 데이터 사용량을 크게 절약할 수 있습니다.


   3. 브라우저 렌더링 효율성
       * 브라우저는 거대한 original 이미지를 다운로드한 후, 화면의 작은 카드 크기에 맞게
         다시 축소하는 작업을 수행해야 합니다. 이 과정은 브라우저에 불필요한 부담을 주어
         렌더링 성능을 저하시킬 수 있습니다.
       * 처음부터 표시될 크기와 유사한 w500 이미지를 제공하면, 브라우저는 이미지를 거의 
         그대로 표시하기만 하면 되므로 렌더링 부담이 줄어듭니다.
